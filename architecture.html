System design / 02

Backend architecture.

A high-level view of how a request flows through the NeoSpider analytics backend — from the tracking script hitting the API, through storage and processing, to what the customer sees in their dashboard and exported reports.

Request & data flow

Diagram
Write / push path Read / request path
00 / CLIENT

Tracked website

Loads the NeoSpider tracking snippet, configured with the customer's site key and any custom page/event tags, and sends pageview and event calls to the API entry point.

01 / EDGE

API entry point

Receives the tracking script's pageview and event calls, plus dashboard and export requests. Handles auth, rate limiting, and validation before anything touches storage.

02 / STORE

Data storage

Durable store for raw events, sessions, and site configuration, alongside precomputed aggregates written back by the analytics engine.

03 / PROCESS

Analytics engine

Aggregates raw events into trends, top pages, referrers, and scores. Runs on a schedule and on demand, writing results back to storage.

04 / VIEW

User dashboard

Reads processed metrics through the API entry point to render live charts and summaries for signed-in customers.

05 / EXPORT

Report exporter

Turns analytics engine output into PDF/CSV files and email digests, triggered on a schedule or by a manual request.

03A / AI

AI pipeline

Branches off the analytics engine to generate plain-language summaries and insights, which the report exporter includes alongside the raw metrics.
